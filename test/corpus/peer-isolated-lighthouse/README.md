# peer-isolated-lighthouse

The Prysm node (Lighthouse's only peer on this two-node devnet) is paused for the full duty window, isolating Lighthouse's validator from its sole source of external attestations and blocks it did not itself produce.


## What was broken

Fault: peer_drop applied to vc-1-geth-lighthouse for 20s, around slot 145.

## Recorded outcome

- Block observed for the duty slot: true (proposer 4, unrelated to the paused
  peer — no confound).
- Attestation published (seen in Lighthouse's own local pool): true, ~18s into
  the slot, well past the 4s deadline. A self-generated attestation reaches a
  node's own pool without needing a peer, so this is not itself evidence
  isolation failed to isolate — it is evidence the whole signing/local-gossip
  path ran slow while cut off, distinctly worth noting rather than glossing
  over.
- Attestation included: never observed within the watch window (up to two
  slots past the duty slot).

## Why this is the cleanest p2p signal generated so far

Unlike the `netem`-based scenarios, nothing about *measuring* this fault runs
through the paused link: Lighthouse's own beacon API stayed directly reachable
throughout, only its path to the wider network (via its one peer) was cut. A
locally-published attestation that never reaches inclusion, with the block
itself unaffected, is a fairly direct demonstration of what
`local.p2p_degraded` describes — propagation, not validation or signing, is
where this failed.
