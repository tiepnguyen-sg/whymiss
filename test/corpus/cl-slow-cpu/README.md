# cl-slow-cpu

The Prysm consensus client's CPU is capped to 7% of one core (cgroup v2 cpu.max) for the full duty window, while its paired execution client runs unthrottled — isolating CL-side validation slowness from EL-side slowness, which local.cl_slow's rule requires (Engine API duration under half of the validation stage). Slots proposed by the faulted Prysm validator set are excluded so the CPU cap cannot turn the scenario into a local proposal miss.
