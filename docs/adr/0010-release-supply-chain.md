# ADR-0010 · GoReleaser + keyless cosign + SLSA generator + syft SBOM

- **Status:** accepted
- **Date:** 2026-08-22
- **Deciders:** maintainers
- **Supersedes:** —

## Context

BUILD_PROMPT §3 locks the release stack by name: "`goreleaser` + SLSA
provenance + cosign + SBOM" — "supply-chain credibility," because the
target user (§1.2) is "deeply suspicious of new software touching their
staking box" and downloads a prebuilt binary rather than auditing and
compiling source. Task 4.7 is the first work that needs to actually wire
this up: `.goreleaser.yaml`, the GitHub Actions workflow that runs it, and
the specific mechanism for each of the three supply-chain properties named
in §3. None of `goreleaser`, `cosign`, or `syft` were previously installed
or invoked anywhere in this repository.

## Decision

**GoReleaser** (`.goreleaser.yaml`, schema `version: 2`) builds
`linux/amd64` and `linux/arm64` static binaries (I-13, matching
`Makefile`'s `build.all` — release build targets are not a separate
decision from CI's cross-compile targets), archives each with
`LICENSE`/`README.md`/`CHANGELOG.md`, and writes `checksums.txt`
(sha256).

**SBOM**: GoReleaser's native `sboms:` block shells out to **syft**
(`artifacts: archive`) and produces one SPDX-2.3 JSON document per
archive — verified locally: `goreleaser release --snapshot --clean
--skip=sign,publish` produced real,
loadable `*.sbom.json` files listing `github.com/tiepnguyen-sg/whymiss` and its
dependency graph.

**Signing**: **cosign, keyless** (Sigstore, GitHub Actions OIDC identity)
signs `checksums.txt` — one signature covers every archive transitively,
since each line of that file is an archive's sha256. Keyless was chosen
over a stored keypair specifically so there is no long-lived private key
for a small open-source project to protect, rotate, or lose custody of;
the signing identity is instead "this exact GitHub Actions workflow, on
this exact repo, triggered by this exact tag," verifiable by anyone
without trusting the maintainers to keep a secret safe. Verified locally
with a throwaway keypair (real keyless verification needs a live GitHub
Actions OIDC token, unavailable outside CI) that the actual command
mechanics work: `cosign sign-blob --yes --key cosign.key
--bundle=checksums.txt.bundle checksums.txt` followed by `cosign
verify-blob --key cosign.pub --bundle checksums.txt.bundle checksums.txt`
→ `Verified OK`. This surfaced a real, current issue: cosign v3 (the
version `brew install cosign` ships today) deprecated
`--output-signature`/`--output-certificate` — the syntax nearly every
public GoReleaser+cosign example still shows — in favor of one combined
`--bundle` file, and **refuses to run at all** without it
(`must specify --bundle with --new-bundle-format`). `.goreleaser.yaml`'s
`signs:` block uses `--bundle=${signature}` accordingly, not the
deprecated flags.

**SLSA provenance**: not generated by GoReleaser itself. A second job in
`.github/workflows/release.yml` calls
`slsa-framework/slsa-github-generator`'s reusable
`generator_generic_slsa3.yml` workflow, pinned by commit SHA, passing it
the base64-encoded contents of GoReleaser's own `checksums.txt` as
`base64-subjects`. That reusable workflow is itself the thing that makes
the provenance trustworthy (SLSA Build L3): it runs in an isolated,
independently-audited job that GitHub, not this project, controls, so a
compromise of this repo's own workflow file can't forge a provenance
attestation claiming otherwise.

## Consequences

**Good**

- Every property BUILD_PROMPT §3 named is produced by a purpose-built,
  widely-used tool for that exact property — no hand-rolled checksum,
  SBOM, or signing logic to maintain or get subtly wrong.
- Verification is entirely public-key / transparency-log based. An
  operator never has to trust "we said we signed it" — `cosign
  verify-blob` against Sigstore's public Rekor log, or the SLSA
  provenance's own verification tooling, checks it independently.
- All new GitHub Actions (`goreleaser-action`, `cosign-installer`,
  `sbom-action`, the SLSA generator) are pinned by commit SHA, matching
  `.github/workflows/ci.yml`'s existing convention ("Pin actions by SHA,
  not tag — supply-chain hygiene the project preaches").

**Bad**

- Three more GitHub Actions dependencies in the release workflow (not
  Go module dependencies — I-14's dependency budget is unaffected). Each
  is maintained by its respective project (GoReleaser, Sigstore, SLSA)
  and is the standard, widely-adopted way to get this specific property;
  hand-rolling any of the three would be more, not less, supply-chain
  surface to maintain.
- Keyless cosign signing only works from within GitHub Actions (it needs
  a live OIDC token from the runner) — a maintainer cannot sign a release
  artifact from their own machine. Accepted: releases are meant to be
  built reproducibly by CI, not assembled locally, so this is a feature
  (no one's laptop is a trusted signing environment) not a limitation.

**Removal path.** Confined to `.goreleaser.yaml` and
`.github/workflows/release.yml` — no runtime code depends on any of
these tools; removing the release pipeline removes nothing from the
binary itself.

## Alternatives considered

**A stored, long-lived cosign keypair** (private key in a GitHub secret).
Rejected: reintroduces exactly the single-point-of-compromise key-custody
problem keyless signing exists to avoid, for a project without a
dedicated security team to manage key rotation and secret storage.

**GoReleaser Pro's built-in SLSA provenance.** Rejected: a paid feature:
BUILD_PROMPT's dependency and tooling choices favor free, standard,
widely-audited tooling over a commercial add-on for a project explicitly
optimizing for "trust" (§1.2) — the community-run
`slsa-framework/slsa-github-generator` is itself more independently
auditable than a vendor's closed implementation.

**Hand-rolled SBOM** (e.g. walking `go.sum` into a minimal JSON document).
Rejected: syft is the de facto standard SBOM generator, produces a
spec-correct SPDX document with license and package metadata a hand-rolled
`go.sum` walk would not capture, and GoReleaser's native `sboms:`
integration makes adopting it near-zero marginal cost over hand-rolling.
